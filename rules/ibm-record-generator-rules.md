# Rules for IBM Record Generator for Java
- When generating Java classes from COBOL copybooks, always use IBM Record Generator for Java instead of manually writing or editing JZOS field mappings.
- The main IBM Record Generator documentation is available at: https://www.ibm.com/docs/en/record-generator/3.0.0?topic=getting-started-record-generator-java
- To generate an ADATA file from a COBOL copybook using the Enterprise z/OS compiler, follow the instructions at: https://www.ibm.com/docs/en/record-generator/3.0.0?topic=cobol-creating-adata-files-enterprise-zos-compiler#cobol_rcg_create_sysdata
  - The ADATA file is generated by compiling a minimal COBOL program that uses a `COPY` statement to include the copybook, with the `ADATA` compiler option and `NOCOMPILE(W)` to suppress object code generation
  - The ADATA output is written to the `SYSADATA` DD in the JCL
  - A single ADATA file can contain metadata for multiple copybooks by including multiple `COPY` statements in the inline COBOL source
- To run `RecordClassGenerator` and generate a Java class from an ADATA file, follow the instructions at: https://www.ibm.com/docs/en/record-generator/3.0.0?topic=cobol-running-recordclassgenerator#cobol_running_rcg
  - Parameters must be specified in `name=value` format — do **not** use dash-prefixed flags (e.g., use `adatafile=` not `-a`)
  - Required parameters are: `adatafile=`, `package=`, `class=`, `symbol=`, and `outputdir=`
  - The `symbol=` parameter specifies the top-level COBOL record name (e.g., `symbol=CUSTOMER-RECORD`) to extract from the ADATA file
  - Example command:
    ```
    java -cp ibm-recgen.jar:ibm.jzos.jar \
      com.ibm.recordgen.cobol.RecordClassGenerator \
      adatafile=CUSTOMER.adata \
      package=com.ibm.cics.cip.bankliberty.datainterfaces \
      class=CUSTOMER \
      symbol=CUSTOMER-RECORD \
      outputdir=src/webui/src/main/java
